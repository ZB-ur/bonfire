### #7 — Skip theatrical reentry from stage-j BLOCKED

| col | value |
|---|---|
| kind | mixed |
| design_question | yes |
| 机械化成本 | M |
| 文档化成本 | S |
| residual 成本 | M |
| 残留风险 | M |
| 决策 | **defer:ASSERTION-5\|design-call-deferred** |

The reentry routes table currently treats all reentries as "reset target stage to pending and re-walk". Real-world routing needs per-route granularity: `handoff_provenance_failure` should reset only J (H verdict still valid); `invalid_stage_j_condition` should reset H (because H's verdict shape is the problem); `handoff_contradiction` is currently → stage-j and that's correct. Adding a `resets_target_stage_status: yes/no` column to reentry_routes is the mechanical part; the design call is which routes need which behavior. This is a self-contained mini-design effort scoped at ~1 day spec + ~1 day implement; not a fit for ASSERTION-4 charter. Defers to ASSERTION-5 with `design-call-deferred` tag.

### #8 — align vs supersede choice

| col | value |
|---|---|
| kind | knowledge |
| design_question | yes |
| 机械化成本 | S |
| 文档化成本 | S |
| residual 成本 | M |
| 残留风险 | M |
| 决策 | **in-scope:ASSERTION-4** |

Skill doc treats `supersede` as primary verb for resolving stale entries; truth-surface implementation requires target to be FROZEN, which CHALLENGED entries (in Stage E closure) are not. Operator falls back to align-via-token. Two fix options: (X) loosen supersede to accept CHALLENGED with rationale, or (Y) skill doc updates to teach align-via-token as primary, supersede as edge case. Strong recommendation to spec-dialectic: option (Y), because supersede semantically implies "FROZEN-truth being amended" which is heavier than "challenged-claim resolved by alignment". Bundled into ASSERTION-4 because it's a doc-vs-implementation invariant drift, parallel to the broader mandate axis principle.
